# Матрица требований итогового проекта

| Требование задания | Реализация | Артефакт проверки |
|---|---|---|
| Не менее четырёх техник курса | Structured IE, RAG/BM25, агент с тремя инструментами, четыре роли, LLM-as-judge | `pipeline.py`, `schemas.py`, `rag.py`, `tools.py` |
| Структурированный вывод | Pydantic v2, `extra='forbid'`, строгие диапазоны и Literal | `schemas.py` |
| Собственный `field_validator` | Проверка даты, точной однострочной цитаты, обязательных инструментов | `schemas.py` |
| Проверка галлюцинаций | Точные цитаты обращения и найденных чанков, source binding, числа только из контекста | `validate_resolution`, `metrics.json` |
| Подсчёт галлюцинаций | Ghost-цитаты считаются после контекстной валидации | `metrics.json` |
| Оценочный набор ≥ 15 | 20 синтетических обращений, разметка скрыта от решающего конвейера | `input/requests.jsonl`, `input/gold.json` |
| Оценка правильности | 7 условий на пример и LLM-as-judge 0–10 | `evaluation.json`, `metrics.json` |
| Оценка траектории | Источник@3, обязательные инструменты, локальная и API-трассы | `pipeline_trace.jsonl`, `api_trace.jsonl` |
| Воспроизводимость | SHA-256 кода/входа, кэш, уникальные response_id, лимит вызовов и бюджета | `run.json`, `artifact_manifest.json`, verifier |
| Данные и ограничения | Явно синтетические регламенты и обращения, без реальных ПД | `input/README.md`, разделы отчёта |
| Отчёт 3–5 страниц | Автоматический отчёт: задача, методы, метрики, ошибки, ограничения, вывод | `output/report.md` |
| Вход и выход | Входные JSONL/Markdown и полный архив результатов | `input/`, `final_project_results.zip` |

Программная проверка подтверждает происхождение, схему, точность строковых цитат и согласованность метрик. Она не подтверждает действительность правил конкретного университета и не заменяет содержательную проверку преподавателем.
