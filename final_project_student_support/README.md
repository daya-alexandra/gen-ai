# Итоговый проект. Academic Navigator

Academic Navigator — учебная система анализа и маршрутизации обращений магистрантов. Проект выполнен по прикладному треку итогового задания. Все обращения и регламенты являются синтетическими и не относятся к реальному университету.

## Цель проекта

Система должна определить содержание обращения, найти относящийся к нему регламент, при необходимости получить контакт или рассчитать интервал дат, а затем сформировать ответ с проверяемыми цитатами. Оценивание учитывает как итоговый результат, так и траекторию решения.

## Архитектура

В конвейере используются пять техник курса:

1. структурированное извлечение категории, намерения, срочности, дат и чувствительных данных;
2. локальный поиск BM25/RAG по пяти регламентам;
3. агент с тремя разрешёнными инструментами: `search_rules`, `get_contact`, `calculate_days`;
4. разделение функций планирования, исполнения, формирования ответа и критики;
5. LLM-as-judge для отдельной оценки итогового ответа.

Цитаты, числовые утверждения и ссылки на источники дополнительно проверяются программно. Некорректный JSON, нарушение схемы или неподтверждённая ссылка приводят к ограниченной повторной попытке. Каждый этап сохраняется отдельно, что позволяет продолжить прерванный запуск.

## Оценочный набор

Оценивание выполнено на 20 синтетических обращениях. Для каждого примера проверяются:

- категория и обязательные поля структурированного извлечения;
- наличие требуемого источника среди первых трёх результатов поиска;
- использование обязательных инструментов;
- отсутствие лишних инструментов;
- корректность цитат и числовых утверждений;
- итоговый ответ по эталонной разметке и вердикту модели-судьи.

## Результаты

| Показатель | Значение |
|---|---:|
| Строгая проверка по эталонной разметке | 17/20 |
| Сохранённые ответы DeepSeek API | 99 |
| Ответы, принятые LLM-as-judge | 20/20 |
| Средняя оценка судьи | 10,00/10 |
| Требуемый источник в первых трёх результатах | 20/20 |
| Полнота обязательных инструментов | 20/20 |
| Неподтверждённые цитаты | 0 |
| Контролируемые защитные проверки | 3/3 заблокированы |

Три непройденных примера сохранены в исходном виде. R07 относится к границе категорий `documents` и `technical`. В R08 и R13 различаются фактическое наличие чувствительных данных в тексте и чувствительный контекст запроса. Во всех трёх случаях требуемый источник найден, а причины расхождения разобраны в отчёте.

## Запуск

Требуется Python 3.10 или более новая версия. На Windows используется файл `RUN_PROJECT.cmd`. Сценарий устанавливает зависимости, выполняет локальные тесты, запускает обработку оценочного набора, проверяет результат и формирует `final_project_results.zip`.

API-ключ задаётся в локальном `.env` и не включается в репозиторий. При повторном запуске завершённые этапы считываются из кэша. Защитные ограничения `LLM_MAX_CALLS=160` и `LLM_BUDGET_USD=3` являются максимальными параметрами программы. Оценочная стоимость завершённого прогона по сохранённому использованию токенов составляет от 0,02119 до 0,04239 доллара США.

## Ограничения

Проект не является официальным сервисом поддержки и не должен использоваться для принятия административных решений. Корпус и обращения синтетические. Высокая оценка LLM-as-judge рассматривается совместно со строгой программной проверкой, а не как самостоятельное доказательство правильности.
