# Лабораторная работа № 4. RAG и сравнение способов разбиения текста

Работа выполнена по заданию семинара 4. Цель — построить RAG-конвейер на собственном корпусе и сравнить две стратегии разбиения документов при неизменных поиске, наборе вопросов и генераторе ответа.

Корпус включает пять авторских документов об учебном проекте общим объёмом 33 583 символа. Эталонный набор содержит 30 вопросов, в том числе вопросы с синонимами, точными идентификаторами и необходимостью использовать несколько источников.

## Методика

Сравниваются две конфигурации:

| Конфигурация | Способ разбиения | Число фрагментов |
|---|---|---:|
| A | блоки по 2000 символов без перекрытия | 20 |
| B | границы абзацев, предложений и слов; до 800 символов; перекрытие 120 | 60 |

Для обеих конфигураций применяется BM25 и единая метрика hit-rate@5. При вопросах, требующих двух документов, наличие только одного обязательного источника даёт половину балла. После поиска ответ формируется через API DeepSeek; цитаты проверяются только по переданным модели фрагментам.

## Результаты

| Показатель | A | B |
|---|---:|---:|
| hit-rate@5 | 0,9000 | 0,9000 |
| Сформированные ответы | 22 | 22 |
| Отказы при недостаточном контексте | 8 | 8 |
| Всего результатов | 30 | 30 |

Сохранено 60 итоговых ответов API. Проверено 138 вхождений цитат; отсутствующие цитаты не обнаружены. Одинаковый hit-rate не означает полного совпадения контекста: в отчёте отдельно разобраны Q15, Q17 и Q19, для которых стратегии возвращали разные фрагменты или различались полнотой ответа.

## Запуск

Требуется Python 3.10 или более новая версия. На Windows используется файл `RUN_LAB3.cmd`. Его техническое имя соответствует каталогу `lab3_rag`; в общей нумерации курса это лабораторная работа № 4.

Ручной запуск из каталога работы:

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
set PYTHONUTF8=1
.venv\Scripts\python.exe -m unittest test_lab3 -v
.venv\Scripts\python.exe pipeline.py all
.venv\Scripts\python.exe verify_results.py --require-api
.venv\Scripts\python.exe collect_results.py
```

Поисковая часть без обращения к API запускается командой `python eval.py`. Для нового независимого эксперимента задаётся отдельный каталог результатов:

```bat
python pipeline.py all --output output_v2
python verify_results.py --output output_v2 --require-api
python collect_results.py --output output_v2
```

API-ключ хранится только в локальном `.env`. Незавершённый запуск может быть продолжен по сохранённому кэшу при неизменных коде, корпусе и эталонной разметке.

## Ограничения

BM25 использует лексическое совпадение и хуже обрабатывает перефразирование без общих слов. Попадание документа в первые пять результатов не гарантирует присутствия требуемого факта в конкретном фрагменте, а корректная цитата не подтверждает логическую правильность всего ответа. Статус сформированного ответа поэтому рассматривается отдельно от его содержательной оценки.
