# Лабораторная № 3 — RAG и сравнение чанкинга

**Статус:** корпус, разметка, код и локальное сравнение поиска готовы. **Генерация ответов через DeepSeek ещё не запускалась.**

[Задание преподавателя](../семинар_4/домашнее_задание.md) · [Отчёт и результаты](output/report.md) · [Происхождение корпуса](CORPUS.md) · [Протокол эксперимента](PROTOCOL.md).

Пять авторских документов о нашем учебном проекте: 33 583 символа, каждый документ длиннее 500 слов. Gold содержит 30 вопросов, включая синонимы, точные идентификаторы и multi-hop. Поиск — BM25 по фиксированным правилам; дополнительные модели и платный API эмбеддингов не нужны. Генерация после retrieval выполняется через DeepSeek с `make_client`, `response_model` и `max_retries=3`.

## Запустить после второй лабораторной

1. Скачай свежий репозиторий **Code → Download ZIP** и распакуй. Папки `lab2_text` и `lab3_rag` должны быть рядом.
2. Выполни вторую работу через `lab2_text/RUN_LAB2.cmd`.
3. Дважды нажми **lab3_rag/RUN_LAB3.cmd**. Если `.env` уже заполнен во второй работе, сценарий скопирует его автоматически. Также можно вручную скопировать заполненный `.env` в `lab3_rag`.
4. Сценарий установит зависимости, выполнит тесты и сравнение поиска, затем отправит **60 запросов генерации** — по одному на каждый вопрос для A и B; невалидные ответы могут потребовать повторов. Проверка цитат, аудит и сбор архива выполняются автоматически.
5. После успешного окончания появится **lab3_results.zip**. Для проверки двух работ передай два отдельных архива: `lab2_results.zip` и `lab3_results.zip`. Ключи и `.venv` в них не входят.

Python 3.10 или новее должен быть установлен. При первом запуске без ключа откроется Блокнот: вставь ключ в `LLM_AUTH_TOKEN`, сохрани файл и закрой окно. Сам ключ отправлять в чат не нужно. При использовании старого `.env` проверь значения `LLM_BUDGET_USD` и `LLM_MAX_CALLS`: копирование сохраняет прежние лимиты. Пример для третьей работы ограничивает оценочные расходы одним долларом и число попыток 120; лимит отдельный для каждой лабораторной.

Если остановилась сеть или API отклонил доступ, исправь причину и запусти тот же сценарий. Принятые ответы сохраняются в кэше и повторно не оплачиваются. После изменения кода, данных или gold нужен новый каталог эксперимента.

## Команды вручную из папки lab3_rag

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
set PYTHONUTF8=1
.venv\Scripts\python.exe -m unittest test_lab3 -v
.venv\Scripts\python.exe pipeline.py all
.venv\Scripts\python.exe verify_results.py --require-api
.venv\Scripts\python.exe collect_results.py
```

Эти команды предполагают уже заполненный `.env`. Для первого заполнения скопируй `.env.example` в `.env` и открой его в Блокноте; не перезаписывай готовый ключ шаблоном.

Только поиск, **без API**: `python eval.py`. Проверить сохранённый retrieval без генерации: `python verify_results.py`.

Свой вопрос: `python pipeline.py ask "Как продолжить обработку после сетевой ошибки?" --strategy B`. Это отдельный платный запрос; он сохраняется в `output/interactive/` и не меняет gold-метрики.

Новый эксперимент: `python pipeline.py all --output output_v2`; затем `python verify_results.py --output output_v2 --require-api` и `python collect_results.py --output output_v2`.

## Сравнение

| Конфигурация | Разбиение | Чанков | hit-rate@5 на 30 вопросах |
|---|---|---:|---:|
| A | Ровно 2000 символов, без перекрытия | 20 | 0,9000 |
| B | Границы абзацев/предложений/слов, до 800 символов, overlap 120 | 60 | 0,9000 |

Метрика считается **точно как в eval.py преподавателя**: доля обязательных gold_sources, представленных среди TOP-5 чанков, усреднённая по вопросам. Для multi-hop одного из двух документов недостаточно для полного балла: это 0,5.

Основная метрика дала ничью. В отчёте отдельно разобраны вопросы, где нужный документ найден обеими стратегиями, но необходимая опорная фраза присутствует только в одной выдаче. Это дополнительные различия контекста, а не искусственно объявленные различия hit-rate. При требовании именно разных HIT/MISS документов потребуется обсудить этот результат с преподавателем; ограничение явно отражено в протоколе и `submission_status.json`.

## Файлы

- `data/` — пять исходных документов; `gold.json` — вопросы и обязательные источники.
- `answer_evidence.json` — диагностические опорные фразы, отдельно от основной gold-метрики.
- `rag_core.py` — чанкинг, смещения, токенизация, BM25 и hit-rate.
- `eval.py` — одинаковое сравнение A/B, полные TOP-5 и отчёт.
- `pipeline.py`, `prompts.py`, `schema.py`, `llm_client.py` — генерация ответов и проверка цитат только по найденному контексту.
- `output/` — реальные локальные результаты поиска. После API-прогона добавятся `answers_A.json`, `answers_B.json`, `generation_metrics.json`, журнал и кэш в `generation/`.
- `verify_results.py` — полный пересчёт retrieval и сопоставление сохранённых ответов с API-журналом. Проверка не вызывает API.

Попадание документа не доказывает наличие нужного факта в выданном фрагменте. Правильная цитата не доказывает логическую верность всего ответа. Синонимы без совпадений слов — ограничение выбранного BM25. Это лексический RAG, а не система семантического поиска с эмбеддингами. Следующий самостоятельный эксперимент может сравнить гибридный вариант, сохранив ту же разметку.

Методика сравнения и определение метрики адаптированы из [paNikitin/gen-ai](https://github.com/paNikitin/gen-ai), `семинар_4/starter/pipeline.py` и `eval.py`, версия курса `5a1325dde011413662b76cab39b906572c8c6d40`. Реализация retrieval самостоятельная, без ChromaDB и загрузки нейросетевого эмбеддера. JSON-клиент перенесён из нашей второй работы; ключи не включены.
