# Ход эксперимента и ограничения интерпретации

1. Подготовлены пять документов и первые 20 вопросов. Основная конфигурация заранее: A — фиксированные блоки 2000 символов; B — границы абзацев/фраз до 800 символов, перекрытие 120. Один BM25, TOP-5 чанков.
2. Пилот на 20 вопросах дал hit-rate@5 = 0,975 у обеих стратегий; вопрос 16 получил 0,5 у обеих. Ни один исходный gold_source не менялся.
3. Дополнительно проверен размер B=400 / overlap=80 из примера семинара: та же средняя метрика 0,975. Эта проверка не стала основной конфигурацией.
4. Для более трудных практических запросов добавлены вопросы 21–30. Первые 20 вопросов сохранены без изменений. На расширенном наборе A и B дали 0,9000; B=400/80 также дал 0,9000. Исходная основная конфигурация B=800/120 оставлена. Победитель по основной метрике не выбирался, потому что наблюдается ничья.
5. Для анализа того, **какая часть документа** попадает в контекст, дополнительно размечены опорные фразы в `answer_evidence.json`. Разметка сделана после наблюдения равных документных метрик. Это диагностика, а не независимый слепой тест и не замена hit-rate@5. Фраза засчитывается только при полном вхождении в один из TOP-5 чанков правильного источника.
6. Отчёт отдельно показывает три примера разного покрытия фактов. Различий попадания gold-документов в TOP-5 не обнаружено. Поэтому буквальное требование примеров разных HIT/MISS документов не следует считать автоматически выполненным: при строгой трактовке преподавателем может потребоваться дополнительный независимый корпус или новый набор вопросов. Примеры разной доступности фактов уже приложены с точными фрагментами и смещениями.

Все измерения поиска выполнены локально без API. Затем пользователь выполнил отдельный API-прогон: 60 итоговых ответов, 61 полученный ответ с учётом повтора A:17. Обе стратегии получили одинаковые вопросы, системный промпт и модель; различался найденный контекст. Числа retrieval не пересчитывались в зависимости от ответов LLM.

Корпус небольшой и тематически хорошо разделён. Длинный чанк иногда захватывает больше нужных сведений, а короткий повышает вес совпадающих слов. В TOP-5 может попасть несколько чанков одного документа, что уменьшает разнообразие источников. Ни одно из этих наблюдений не доказывает универсального преимущества конкретного размера.

После API-прогона доработан отчёт: Q15 и Q17 показали answered у B и insufficient_context у A; Q19 — обратное. Для каждого примера проверены конкретные фрагменты, их ранги и содержание ответа. Это разница наличия фактов и полноты ответа, при неизменной одинаковой документной метрике. Полные данные последующего разбора находятся в output/report_review.json.
