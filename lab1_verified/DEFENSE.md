# Что объяснить на защите

1. **Зачем нужны две модели?** `Application` описывает всю заявку, а вложенная
   `Address` содержит город и район. В CSV адрес распаковывается в два столбца.

2. **Что проверяет Pydantic?** Диапазоны, типы, разрешённые специальности
   и курсы, лишние поля. Четыре пользовательских валидатора проверяют город,
   формат ФИО, стаж не больше возраста минус 18 и возраст выпуска не меньше 20.
   Возраст фиксируется на конец 2026 года. Последние два условия — допущения
   учебного датасета, а не универсальные правила биографий.

3. **Что значит `max_retries=3`?** Первоначальный ответ и до трёх исправлений
   неверного JSON или нарушения схемы. Ошибки API останавливают работу. Здесь
   все 100 ответов приняты с первой попытки. Повторы проверялись отдельно на
   намеренно некорректных тестовых объектах.

4. **Что изменили квоты?** Максимум по городу снизился с 18% до 10%.
   Специальности не квотировались: максимум вырос с 30% до 32%.
   Одного прогона на стратегию недостаточно для причинных выводов.
   Число вариантов в схеме не гарантирует появления всех вариантов в выборке.

5. **Какие ограничения остались?** В итоговом наборе нет учителей. У 32 из 50
   заявителей возраст 34 года, пять ФИО повторяются по два раза. Полностью
   одинаковых строк нет. Городские квоты не устраняют эти перекосы.

6. **Как улучшить генератор?** В новом эксперименте ввести возрастные группы
   и квоты специальностей, проверять уникальность ФИО по всему набору,
   нормализовать районы по справочнику. Сейчас промпт помнит только пять
   последних ФИО. Эти улучшения не выдаются за выполненные эксперименты.

7. **Что воспроизводит seed?** Расписание городов и перемешивание вариантов
   специальностей. Ответы и версия модели у провайдера могут измениться.
   Поэтому сохранены исходные ответы, идентификаторы и хеши кода.
