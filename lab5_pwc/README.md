# Лабораторная работа № 6. Архитектура «Планировщик — Исполнитель — Критик»

Работа выполнена по заданию семинара 6. Цель — проверить многоагентную схему на устойчивость, добавить валидацию плана, реализовать параллельное выполнение независимых подзадач и измерить надёжность критика.

## Реализация

После формирования плана проверяются имена инструментов, идентификаторы подзадач и зависимости. План с ошибками передаётся планировщику повторно вместе с описанием обнаруженных нарушений. Исполнитель получает только результаты тех подзадач, от которых зависит его текущая задача.

Независимые подзадачи одного уровня выполняются через `ThreadPoolExecutor` с числом потоков не более трёх. При повторной обработке сохраняются корректные независимые ответы, а повторно выполняются только указанные критиком узлы и зависящие от них узлы.

Эксперимент включает три части:

| Часть | Объём |
|---|---:|
| 6 вопросов, 3 конфигурации, 5 повторов | 90 запусков |
| 5 повреждённых наборов, 2 температуры, 10 повторов | 100 испытаний критика |
| Q1 и Q5, последовательное и параллельное исполнение | 12 замеров |

Сравниваются одиночный агент, PWC без валидатора и PWC с валидатором. Для проверки гарантированно исправляемого случая используется отдельный детерминированный контроль: в план вводится отсутствующий инструмент, после чего проверяются обнаружение ошибки, повторное планирование и последующее выполнение. Этот контроль не включается в статистику естественных ответов модели.

## Данные и критерии

Используется учебный снимок макроэкономических данных на 22 апреля 2026 года. Показатель `cpi_yoy` представляет темп год к году, поэтому запрос, требующий 51 помесячный индекс, получает обоснованный отказ. Такой отказ считается корректным и не заменяется расчётом по неподходящим данным.

Критик получает план, итоговые ответы и перечень использованных инструментов, но не видит полную внутреннюю трассу. Любой вердикт `ok=True` для заранее повреждённого набора учитывается как ложное принятие. Ошибки формата и противоречивые вердикты фиксируются отдельно.

## Запуск

Требуется Python 3.10 или более новая версия. На Windows используется файл `RUN_LAB5.cmd`. Сценарий устанавливает зависимости, выполняет локальные тесты, запускает эксперимент, проверяет сохранённые данные и формирует `lab5_results.zip`.

Ручной запуск из каталога `lab5_pwc`:

```bat
set PYTHONUTF8=1
.venv\Scripts\python.exe -m unittest test_lab -v
.venv\Scripts\python.exe run_lab.py
.venv\Scripts\python.exe verify_results.py
.venv\Scripts\python.exe collect_results.py
```

Новый независимый эксперимент выполняется с параметром `--output output_v2`. API-ключ хранится только в локальном `.env`. Значения `LLM_BUDGET_USD=5` и `LLM_MAX_CALLS=2500` задают предельные условия программы и не являются фактической стоимостью.

## Ограничения

Результаты показывают, что усложнение архитектуры само по себе не гарантирует повышение доли правильных ответов. Валидатор устраняет определённые ошибки структуры плана, но не исправляет неточности интерпретации данных или критериев ответа. Сравнение времени относится только к зафиксированным планам Q1 и Q5.
