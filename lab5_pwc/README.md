# Лабораторная № 5 — Планировщик, Исполнитель, Критик

**Подготовлена к реальному API-прогону.** Код и локальные проверки готовы. Реальные доли прохождения, ложные принятия критика и ускорение ещё не измерены.

Основание: [домашнее задание семинара 6](https://github.com/daya-alexandra/gen-ai/blob/main/семинар_6/домашнее_задание.md). Это пятая отдельная домашняя работа в нашей нумерации; отдельной шестой домашней работы в репозитории курса нет. Вводный семинар 1 и финальный проект не включены в этот комплект.

## Запуск на Windows

1. Распакуй `labs_remaining_ready.zip` и сохрани папки `lab4_agent` и `lab5_pwc`. Сначала удобно запустить четвёртую работу, затем эту.
2. Открой **RUN_LAB5.cmd**. Он сам выберет папку, включит UTF-8, установит зависимости и выполнит локальные тесты.
3. Ключ перенесётся из соседней `lab4_agent`, `lab3_rag` или `lab2_text`. Если ключа нет — заполни `LLM_AUTH_TOKEN` в открывшемся Блокноте, сохрани и закрой его. Нажми любую клавишу в окне сценария. Ключ в чат не отправляй.
4. Оставь окно открытым. После строки **Finished** пришли **lab5_results.zip** из папки работы. По нему можно окончательно проверить отчёт и реальные выводы.

Python 3.10+. Эта работа существенно длиннее предыдущих: число API-запросов больше числа экспериментальных запусков, потому что у каждого агента несколько шагов. Оценочное время заранее не фиксируется.

## Что будет выполнено

| Часть | Объём |
|---|---:|
| 6 вопросов × 3 конфигурации × 5 повторов | 90 запусков |
| 5 битых входов × 2 температуры × 10 повторов | 100 вызовов критика |
| Q1 и Q5 × 3 пары последовательного/параллельного исполнения | 12 замеров |
| Отдельный контроль валидатора с намеренной инъекцией | Без API |

Одиночный агент, PWC без валидатора и PWC с валидатором используют один и тот же ReAct-цикл и четыре исходных инструмента. `agent.py` перенесён из четвёртой работы без изменения цикла; `agent_s5.py` — тонкая обёртка выбора четырёх инструментов. Добавление валидатора не изменяет одиночного агента.

После планировщика проверяются имена инструментов, id и зависимости. Невалидный план перепланируется до исполнения. Подвопросы одного уровня идут через ThreadPoolExecutor, максимум три одновременно. Исполнитель получает только ответы своих зависимостей. После rework повторяются указанные узлы и их потомки, а корректные независимые ответы сохраняются.

Критик видит план, финальные ответы и `used_tools`; сырая трасса скрыта. Пять повреждённых наборов заданы заранее в `critic_cases.py`. Каждый повтор T=0.0 и T=0.7 — отдельный запрос с уникальным идентификатором этапа; одинаковые ответы не размножаются из кэша. В измерении критика JSON-ошибка не запускает дополнительную попытку внутри испытания. Любое `ok=True` считается ложным принятием; ошибки формата и противоречивые вердикты отмечаются отдельно.

## Как понимается «гарантированно исправляемый» вопрос

Обычный API-вопрос Q4 содержит риск выдуманного имени `get_policy_rate_range`. Нельзя гарантировать, что вероятностная модель обязательно ошибётся в пяти повторах. Поэтому гарантия проверяется **отдельным детерминированным контролем**: фиксированный сломанный план, реальный диспетчер инструментов и скриптовая перепланировка после обратной связи. Он ловит `get_policy_rate_range` и `get_cumulative_inflation` и доказывает порядок «валидатор → исправление → исполнитель».

Этот контроль честно отмечен как локальная инъекция без API. Его результат не подменяет ячейку Q4 основной таблицы 6×3. Если преподаватель требует гарантированного выигрыша именно на естественных ответах LLM, такое условие не гарантируется кодом; фактический результат будет виден только после прогона.

## Данные и корректный отказ

Фиксирован тот же учебный снимок **2026-04-22** из CSV стартера. Есть синтетические значения; это не актуальная официальная статистика. «Сегодня» означает дату снимка.

Q3 требует 51 помесячный прирост ИПЦ, а CSV содержит только `cpi_yoy` — темп год к году. Обоснованный отказ с этой причиной считается корректным для всех трёх конфигураций. Перемножение годовых темпов не используется.

## Измерение времени и стоимость

Для Q1 и Q5 обе конфигурации исполняют одинаковые планы, зафиксированные заранее в `benchmarks.py`. Измеряется только wall time исполнителей, без планировщика/критика/синтеза; три пары с чередованием порядка. Локальный кэш не используется для нового замера. При прерывании незавершённый замер начинается заново; он не выдаётся за ускоренный запуск из кэша.

В отчёте учитываются пары с корректными ожидаемыми числами и инструментами. Все неудачные замеры тоже сохраняются. Ускорение менее 1 честно означает замедление; при отсутствии валидной пары число ускорения не выдумывается.

По умолчанию: `LLM_BUDGET_USD=5`, `LLM_MAX_CALLS=2500`. **Это пределы программы, не стоимость работы и не требование пополнить счёт на $5.** Фактический расход зависит от длины планов, ответов и повторов. Тарифы Flash проверены 19.09.2026 по [официальной странице](https://api-docs.deepseek.com/quick_start/pricing/); расчёт и полный usage будут в отчёте. При необходимости лимит можно изменить в локальном `.env` и продолжить тот же запуск.

Копируются только ключ, модель и адрес API, а не старые маленькие лимиты предыдущей работы. Заполненный `.env` не перезаписывается. При сетевой ошибке, исчерпании бюджета или закрытии окна снова запусти тот же CMD: завершённые этапы сохранятся. Код и CSV во время эксперимента не меняй.

## Команды вручную

Из папки `lab5_pwc`, после установки `requirements.txt` и заполнения `.env`:

```bat
set PYTHONUTF8=1
.venv\Scripts\python.exe -m unittest test_lab -v
.venv\Scripts\python.exe run_lab.py
.venv\Scripts\python.exe verify_results.py
.venv\Scripts\python.exe collect_results.py
```

Новый эксперимент: `python run_lab.py --output output_v2`. Тот же путь нужно передать проверке и сборке: `python verify_results.py --output output_v2`, `python collect_results.py --output output_v2`.

Отдельный вопрос: `python orchestrator.py "Какова накопленная инфляция с января 2022 по март 2026?"`. Для одиночного агента есть `agent_s5.py`; для PWC доступны `--no-validator` и `--sequential`.

## Файлы после прогона

`output/report.md` содержит пять разделов задания. `eval_results.json` — 90 результатов; `critic_trials.json` — 100 испытаний; `timings.json` — все замеры; `metrics.json` — пересчитанные таблицы. В `generation/` сохраняются исходные ответы API и расход; в `tasks/` — завершённые этапы. `validator_control/` отделён от реальных API-результатов. Итоговый ZIP не содержит ключ и виртуальное окружение.

Проверка без API сверяет количество отдельных ответов, температуры, отсутствие raw_trace в запросах критика, инструменты и числа, кэш и журнал, таблицы и целостность файлов. Она не подменяет последующее чтение ответов человеком.
