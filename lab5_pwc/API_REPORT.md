# Лабораторная работа № 6. Планировщик — Исполнитель — Критик

**Режим: реальный API-прогон**

## 1. Валидатор схемы

`validate_plan(plan: Plan) -> list[str]` проверяет имена инструментов, пустой список инструментов, повтор id/зависимостей, несуществующие зависимости и циклы. Ошибка вызывает перепланировку до запуска любого исполнителя; максимум три попытки. Существуют только get_fx_rate, get_key_rate, get_inflation, calculate.

```json
{
  "plan": {
    "reasoning": "Контролируемая инъекция неизвестного имени.",
    "subquestions": [
      {
        "id": 1,
        "question": "Ставка 2024-10-28",
        "expected_tools": [
          "get_policy_rate_range"
        ],
        "depends_on": []
      }
    ]
  },
  "errors": [
    "1: инструменты не существуют: ['get_policy_rate_range']"
  ]
}
```

```json
{
  "plan": {
    "reasoning": "Вторая фантомная функция.",
    "subquestions": [
      {
        "id": 1,
        "question": "ИПЦ",
        "expected_tools": [
          "get_cumulative_inflation"
        ],
        "depends_on": []
      }
    ]
  },
  "errors": [
    "1: инструменты не существуют: ['get_cumulative_inflation']"
  ]
}
```

Контролируемая проверка Q4: одиночный диспетчер и PWC без валидатора отвергают инъекцию; PWC с валидатором получает обратную связь и исполняет исправленный план. Планировщик в этой проверке скриптовый, инструменты настоящие локальные, API-вызовов нет. Гарантия относится именно к фиксированной инъекции. В обычном API-eval Q4 все три конфигурации могут справиться: вероятностную галлюцинацию нельзя гарантировать промптом.

## 2. Параллельность

Для Q1 и Q5 использован один и тот же заранее заданный валидный план в последовательном и параллельном режимах. Три пары измерений; порядок чередуется. Измеряется wall time только исполнителей, без планировщика, критика и синтеза. Ответы API имеют новые ключи этапов; локальный кэш не ускоряет эти замеры.

| Вопрос | Последовательно, медиана с | Параллельно, медиана с | Ускорение |
|---|---:|---:|---:|
| Q1 (3 валидных пар) | 5.875 | 4.299 | 1.367× |
| Q5 (3 валидных пар) | 6.600 | 4.133 | 1.597× |

Сравниваются только пары, где обе стороны дали нужные числа и вызвали ожидаемые инструменты. Все исходные замеры, включая неуспешные, сохранены в timings.json. Значение менее 1 означает замедление, оно сохраняется без исправления. Малое число пар и изменение задержек API ограничивают вывод; кэш провайдера может влиять на время.

## 3. Замер критики

Пять заведомо повреждённых входов × две температуры × 10 отдельных API-вызовов. Внутри одного испытания нет автоматического повтора JSON-валидации. raw_trace критик не получает. Любое ok=true считается ложным принятием, в том числе при противоречивом action; ошибки формата отмечены отдельно и не засчитываются как правильное отклонение.

| Битый кейс | T=0.0, ложных принятий | T=0.7, ложных принятий | Ошибки формата 0.0 / 0.7 |
|---|---:|---:|---:|
| Арифметика без calculate | 0/10 | 0/10 | 0 / 0 |
| Выдуманное число | 0/10 | 0/10 | 0 / 0 |
| Несогласованные зависимости | 0/10 | 0/10 | 0 / 0 |
| Нет одного обязательного ответа | 0/10 | 0/10 | 0 / 0 |
| Ошибка инструмента вместо данных | 0/10 | 0/10 | 0 / 0 |

Число ложных принятий одинаково: этот опыт не показывает, что повышение температуры лечит соглашательство.

T=0 также вызывается десять раз: одинаковые ответы не подменяются одной копией. Это повторяемость поведения API, не гарантия статистической независимости. Число исходных кейсов мало, доверительные выводы по качеству в целом не делаются.

## 4. Eval 6 × 3 — проверенный счёт

Перепроверка сохранённых ответов и трасс дала **79 из 90** успешных запусков. Ответы модели, вызовы API и наблюдения инструментов не изменялись; исправлены только очевидные ложные отрицания исходного текстового валидатора.

| id | Одиночный N=5 | PWC N=5 | PWC + валидатор N=5 |
|---|---:|---:|---:|
| Q1 | 5/5 | 5/5 | 5/5 |
| Q2 | 5/5 | 3/5 | 0/5 |
| Q3 | 5/5 | 5/5 | 5/5 |
| Q4 | 5/5 | 4/5 | 5/5 |
| Q5 | 5/5 | 5/5 | 5/5 |
| Q6 | 5/5 | 4/5 | 3/5 |
| **Итого** | **30/30** | **26/30** | **23/30** |

### Почему исходный отчёт показывал 51/90

- Q3: два корректных отказа одиночного агента содержали слово «помесячного», а исходная проверка искала только фрагмент «нет месяч». После смысловой проверки все 15 ответов корректны.
- Q4: 14 ответов правильно сообщают снижение с 21% до 16% на 5 п.п. Исходный парсер не понимал типографский минус `−`, а также не учитывал формулировку «снизилась на 5». Один PWC-прогон действительно завершился структурной ошибкой `Противоречивый вердикт критика`.
- Q6: 12 ответов правильно получили 1650 ₽ расхода и 350 ₽ остатка, но проверка требовала буквальное `руб` и не принимала символ `₽`. Ещё три запуска действительно дали излишний отказ из-за ошибочного вывода Планировщика о неоднозначном направлении курса.
- Q2 оставлен по исходному строгому критерию `16 − 6,8 = 9,2`. Четыре непринятых ответа корректно вычисляют 8,61% по формуле Фишера; это содержательно обоснованная альтернативная трактовка, но она не включена в счёт 79/90. Остальные ответы-отказы показывают неоднозначность формулировки про «последний месяц» при наличии только показателя г/г.

### Что показало сравнение

В этом прогоне одиночный агент оказался стабильнее: 30/30 против 26/30 у PWC и 23/30 у PWC с валидатором. Сильная модель справилась с прямыми вопросами без декомпозиции, а дополнительные этапы создали новые точки отказа: выбор другой формулы, пустой формально допустимый план и противоречивый вердикт критика.

Schema-Validator выполнил свою узкую задачу: в контролируемой инъекции он остановил фантомный `get_policy_rate_range`, получил исправленный план и ответ −5 п.п. Однако структурно допустимый план не гарантирует правильной интерпретации вопроса; именно это видно по Q2 и Q6.

## 5. Итоги экспериментов

- Параллельное исполнение ускорило Q1 в 1.367 раза и Q5 в 1.597 раза по медиане трёх валидных пар.
- Критик дал 0 ложных принятий во всех 100 испытаниях; ошибок формата не было. Различия между T=0,0 и T=0,7 в этом наборе не обнаружены.
- Контролируемая проверка валидатора прошла: обычный PWC исполнил фантомный инструмент и не дал результат, валидированный вариант перепланировал задачу разрешёнными инструментами.
- Получено 723 ответов API, 610390 входных и 73670 выходных токенов. Расчётная стоимость: $0.07484–$0.14968; серверный биллинг отдельно не проверялся.
