# Проверка лабораторной № 2

19.09.2026, Python 3.12, Linux. Команда: `python -m unittest test_lab2 -v`.

**13 тестов пройдены.** Проверены дата из будущего, отсутствие аспекта, шесть уникальных аспектов, цитата из чужого отзыва, изменение отрицания и числа, полнота разбиения, учёт cache hit в тарифе, ограничитель бюджета до отправки запроса, безопасная обработка API-ошибки без повторов, ровно четыре попытки при max_retries=3, отказ от возобновления при изменении конфигурации и полный конвейер на заглушке.

Интеграционный тест проверяет ветку judge < 0,7 → изменённый REDUCE → повторный judge, отдельный контроль A99, отсутствие повторных вызовов при возобновлении, совпадение сохранённых результатов с ответами и отказ проверять тестовую заглушку как настоящий API-прогон. Изменение результата IE обнаруживается проверкой.

Для тестов используются временные каталоги, которые удаляются после выполнения. Их оценки и heatmap не публикуются в `output/`. Windows-сценарий подготовлен для CMD, но на Windows в этой среде не запускался.

**Реальный прогон DeepSeek завершён.** Итоговые сводка, judge и все обязательные артефакты получены; доработанный отчёт содержит два примера неточностей из основного конвейера.

## Исправление загрузки настроек

19.09.2026 после пользовательского запуска воспроизведён сбой `test_budget_blocks_before_request`: локальный `.env` перезаписывал нулевой бюджет теста. До исправления получено то же `AssertionError: 4 != 0`. Клиент с тестовым транспортом теперь не загружает `.env`; обычный API-режим сохраняет загрузку настроек. Регрессионная проверка создаёт отдельный `.env` с ненулевым бюджетом и подтверждает блокировку до первого тестового вызова. После исправления весь набор из 13 тестов проходит без API. Во второй лабораторной отдельно проверено сохранение загрузки `.env` для обычного режима без отправки запроса.
