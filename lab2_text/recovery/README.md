# Продолжение второй лабораторной

В полученном 19.09.2026 архиве `output.rar` сохранены 30 объектов IE, оценки
всех шести аспектов и пять MAP-сводок. Прогон остановился на REDUCE: четыре
ответа по 5000 токенов завершились с `finish_reason=length`. Модель продолжала
перечислять частные наблюдения вместо короткой итоговой сводки.

## Установить небольшое обновление

1. Распаковать `lab2_resume_update.zip` в отдельную временную папку.
2. Скопировать папку `lab2_text` из обновления внутрь уже существующей
   `gen-ai-main` на рабочем столе. Подтвердить замену совпадающих файлов.
3. Открыть прежнюю `gen-ai-main/lab2_text` и запустить `RUN_LAB2.cmd`.

Старую папку перед копированием не удалять. В обновлении нет `.env`, `output/`,
`.venv` и семи базовых `.py`-файлов, хеши которых записаны в исходном прогоне.
Сохранённый ключ, кэш и результаты остаются на месте. Это обновление второй
работы; третью менять не нужно.

## Что изменилось

`continue_lab2.py` вызывает тот же `pipeline.analyze` с дополнительным профилем
запросов. IE, аспектный анализ и MAP используют прежние схемы, промпты и ключи
кэша. Их принятые ответы повторно не отправляются в API.

Для REDUCE теперь схема допускает 3–5 групп наблюдений и 2–3 действия,
не более двух цитат на пункт; максимальная длина ответа — 12000 токенов.
Для judge и autodiscovery также ограничена многословность, с лимитами 10000
и 8000 токенов. Оценки не исправляются автоматически: сохранены исходная
рубрика judge, порог 0,7, повторная сводка при низкой оценке и строгая проверка
цитат. Лимиты ниже указанного для Flash максимума в
[документации DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/),
проверенной 19.09.2026. Увеличенный предел не означает, что модель обязательно
потратит всё разрешённое количество токенов.

Профиль, SHA-256 дополнительного кода, схемы и инструкции записываются в
`output/continuation.json`. Там же сохранены исходные метаданные, бюджет,
хеши старого кэша и префикса журнала. Новые ответы продолжают тот же журнал;
прежние ошибки и их usage не удаляются. Общие метрики включают оба запуска.
Изменения профиля после начала продолжения отклоняются до новых запросов.

Для запуска вручную из `lab2_text`:

```bat
.venv\Scripts\python.exe recovery\continue_lab2.py
.venv\Scripts\python.exe collect_results.py
```

Проверка без API:

```bat
.venv\Scripts\python.exe recovery\continue_lab2.py --verify-only
```

После успешного завершения `RUN_LAB2.cmd` создаст `lab2_results.zip`.

## Локальная проверка обновления

Пять дополнительных тестов проходят на Python 3.12 / Linux. Они воспроизводят
четыре обрыва REDUCE, проверяют продолжение только с оставшихся стадий,
сохранение 17 принятых ответов и префикса журнала, ветку повторного judge,
нулевое число новых вызовов при повторном запуске завершённой работы,
ограничения размера сводки, обнаружение подмены кэша, журнала и профиля,
а также первый запуск с пустым каталогом. Все ответы в этих тестах — заглушки
с явной меткой `offline_test`; проверка по умолчанию не принимает их как API.
Windows-сценарий в этой Linux-среде не исполнялся. Успех реальной генерации
нужно проверить после запуска пользователем.

В переданном частичном API-прогоне отдельно сверены все 17 сохранённых стадий
с их ключами кэша, журналом, схемами и источниками. В сохранённых IE, аспектах
и MAP проверена 321 цитата: отсутствующих в соответствующих отзывах — 0.
Это проверка наличия текста; она не доказывает правильность каждой интерпретации.

Подлинных итоговой сводки, judge и autodiscovery в исходном архиве нет.
Получать их должен реальный API. Завершённые тестовые ответы из локальной
проверки не публикуются как результаты лабораторной.
